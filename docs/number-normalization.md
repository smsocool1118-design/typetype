# 阿拉伯数字 vs 汉字数字：转写归一化规范

本规范定义 typetype 在语音转写归一化（`electron/text-normalization-engine.ts`）里，什么时候把口述数字转成阿拉伯数字、什么时候保留汉字。依据国家标准 **GB/T 15835《出版物上数字用法》**，并结合语音输入场景做了保守取舍。行为由 `test/text-normalization-engine.test.js` 的 `SPEC:` 用例锁定，改规则须同步更新用例。

## 一、用阿拉伯数字（半角、小写）

| 场景 | 例（口述 → 输出） | 实现 |
|---|---|---|
| 公历年月日 | 二零二五年六月六日 → `2025年6月6日` | `normalizeDates` |
| 时刻 | 下午三点半 → `下午3点半` | `normalizeTimes` |
| 百分比/比率 | 占比百分之三十 → `占比30%` | `normalizePercentages` |
| 金额 | 一百块钱 → `100块钱` | `normalizeMoney` |
| 电话/编号/工号/验证码 | 手机号一三八… → `138…` | `normalizePhoneNumbers` / `normalizeIdentifierNumbers` |
| 版本号 | 零点五点三 → `0.5.3` | `normalizeVersionNumbers` |

配套清理（0.5.3 起）：
- `collapseNumberUnitSpacing`：去掉数字与中文日期/量词单位间残留空格（`8 月 2 日` → `8月2日`）。
- `mergeGluedChineseArabicYear`：丢弃粘连阿拉伯年份的冗余中文数字前缀（`二零2026年` → `2026年`）。
- 中英混排空格只在**含字母**的英文词/缩写与中文之间加（`GPT模型` → `GPT 模型`），纯数字+单位不拆开（见 `code-switch-lexicon.ts` `normalizeMixedSpacing`）。

## 二、保留汉字（不转阿拉伯）

| 场景 | 例 | 说明 |
|---|---|---|
| 成语/定型词中作语素的数字 | 风和日丽、一心一意、十全十美、五花八门、七上八下 | 数字是词的语素，非计量。`IDIOMS_TO_PRESERVE` + 规则不触发 |
| 概数/约数 | 三四个、五六十、十几、几十、一两天、二十来个 | 无通用"计数→阿拉伯"规则，天然保留 |
| 序数（定型/口语） | 第一名、第二季度、第三点意见 | `(?<!第)` 等守卫避免误当时间/计数 |
| 星期 | 星期六、周三 | `WEEKDAY_RE` 保护 |
| 单独的十/百/千作约数 | 十来个、上百人 | 保留 |

## 三、边界与取舍

- **小整数计数**（如"十个苹果"）保留汉字，不强制转 `10个`：避免"一个/两个/十分/几分"等被误转，语音场景更稳。需要严格阿拉伯计数时再单列白名单。
- **成语保护优先**：成语/定型词在数字规则前通过 `protectValues` 占位，确保 `风和日丽`、`一元复始` 等永不被日期/金额规则改写。
- **重复字不属于本规范**：`风风和和日丽丽`、`占占比` 是识别层叠字/口吃，由删除实时 transducer（改用离线 SenseVoice）+ `transcript-cleanup.ts` 的去重兜底处理，不在数字归一化职责内。
